## Cancellation, failures and replay

The new classifier-gate probe waits for an independently written ready record,
sends and flushes the original `notifications/cancelled`, then releases the
classification before its admission deadline. On main the valid Read classifier
reply is emitted and reports Allow, then unsupported/concurrent transport refusal
closes the gateway: zero executor entries, zero original call-result bytes.
This is one bounded negative sample, not advertised cancellation support.

The native-gate regression adds two fresh real-baseline sessions: cancellation
sent after the actual native call endpoint is reached, then either keep admission
stalled until timeout or release it. It separately records an executor ledger-file
creation and any complete dispatch. A file created but interrupted before its
complete record still proves a side effect, even if complete-record count is zero.
A queued cancellation does not promise immediate refusal or rollback; when native
Allow returns, the original allowed call may already reach the child before
transport refusal. The original result is withheld. The report does not turn an
empty payload or `executed: false` into proof of no effects.

Seven existing lifecycle cases now use actual rule-baseline/Python and check its
source hash, original arguments/IDs, scores and composition telemetry: post-manifest
outage, admission timeout, result-stage outage, same-daemon isolation/followup,
restart/fresh session, exact/changed-payload replay, and allowed executor error
after an effect. Native trusted policy remains an additional gate; classifier
composition Allow alone does not assert that a dead daemon was consulted.
Unsupported batch/concurrent capabilities remain refused rather than simulated.

## Metrics and accepted limits

The paired read measurement uses identical original calls, arguments, metadata,
fixture notes and results in persistent protected/direct sessions. Order alternates;
one warmup pair and session startup are excluded. Per-call Python process startup,
collector, native admission/result inspection and fixture execution stay inside
protected request latency. Direct access is a measurement control only.
Nearest-rank percentiles with 30 observations make p99 the observed maximum;
this is a designed local sample, not a population performance guarantee.

Final paired run: direct p50 **0.233 ms**, protected p50 **38.353 ms**;
paired overhead mean **38.498 ms**, p50 **38.070 ms**, p95 **42.545 ms**,
p99 **45.240 ms**. All 30 measured protected calls executed exactly once and
released the original useful result. Zero fixture false interruptions are **0/30**;
the two standalone overlap positive controls are separately **0/2**, not pooled
into a population rate. The earlier preliminary measurement was 37.110 ms mean;
only the final frozen strict-grader run is used for these reported percentiles.

False interruptions are reported for declared useful Allow controls. Expected Ask
and unsupported combinations are not false blocks. Classification accuracy,
uncertainty calibration and held-out false-interruption rates are not measured;
synthetic replies and provisional demo labels cannot establish classifier quality.

[Accepted contract section 8](../../../contract/updated_contract2.md) requires zero
forbidden executions, one independent executor observation and inspected result
